# Agent Evaluation 的范围

项目的 Evaluation 面向真实 `create_agent` 图、业务工具和受控业务环境，检查用户目标、工具轨迹、数据库终态与最终回复。它不把 Telegram Webhook、Receipt、Sender 和真实消息送达计入同一个 Agent 成功率；这些链路需要独立集成测试和真人联调。

历史材料包含 H3 的 24 条分层任务与 U 的 16 条冻结未见任务。U 首次冻结之后已参与问题定位，不能再次称为全新未见集。不同实验中的模型、时间、工具定义和评分协议也可能不同，不能把历史结果直接混成当前版本的综合通过率。原始轨迹及带私人信息的本地运行材料不随公开副本提供。

评分优先使用 Ground Truth 与业务终态的确定性 Oracle；必要的工具顺序、审批和非预期写入也要核对。可选统一 LLM Judge 在可信证据包上判断任务语义和工具故障处理，但不能推翻确定性业务失败。Judge 的真实调用需要自己的 API 配置与费用授权；离线 Replay 不是新一次被测 Agent 运行。缺少证据时记录待定，而不是默认通过。

本副本提供 `agent_benchmark/`、协议、审计和部分脱敏报告，适合阅读评测设计及运行无需外部服务的测试。历史成绩和阶段实现细节见 `docs/engineering/`；任何新基线均须在同一模型与环境下重新运行，不得引用旧数字当作当前线上表现。
