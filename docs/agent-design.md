# Agent 设计

## 框架和项目各负责什么

LangChain `create_agent` 结合 LangGraph 提供模型与工具的循环：模型看到工具名称、描述和参数 Schema，生成 Tool Call；框架执行工具并把 ToolMessage 交回模型，直到模型回复或进入审批中断。Checkpoint 保存图状态，支持恢复。这些循环和图能力来自框架。

项目自行定义 Todo、Calendar、Gmail 和提醒等业务工具，控制对模型可见的工具集合，并在执行端再次校验可信用户、资源归属、参数和版本。模型写出的身份或“我有权限”不可信，Prompt 也不能代替服务端授权。模型提出 Tool Call 只是一项请求，不代表数据库或 Google 已写入。

## 工具依赖与审批

“先查日历，再按空档创建 Todo”存在真实的数据依赖：模型只有收到成功的候选空档后才能选择时间。执行端会核对本轮已返回的候选与目标及时间是否匹配；没有候选、查询失败或不匹配时拒绝把猜测时间作为可信排期。独立任务可并行，但同一轮并行提出的两项调用不会自动形成先后依赖。

需要审批的操作会在工具执行前中断。审批是用户对具体提案的决定，随后仍需检查身份、目标和版本。一个会话可能同时有多个待审操作；批准其中一项后，其工具结果可能已保存，但 Agent 仍等待其余决定。恢复逻辑必须以具体操作和工具结果为证据，不能仅凭主 Checkpoint ID 是否变化推断业务完成。

## 记忆、失败和输出

Checkpoint 管当前线程的短期对话状态；数据库里的 Todo 是业务事实，不因裁剪模型上下文而消失。当前默认记忆模式是来源限定的原话检索和 Profile Store；历史向量实验不能直接当成默认生产能力。线程标识只帮助找回会话，不能代替身份验证。

只读外部请求可做有限重试；远端写入结果未知时须核对，不能当作普通读取重试。工具结果、业务状态与模型最终文字需区分：模型说“成功”不是写入证明。系统保留独立的入站、业务执行和出站记录，降低重试时重复操作或丢失回复的风险，但不提供端到端 Exactly-Once。
